## What exists today (facts)
### Launch path
Pegasus (Qt 5.15, wrapped in os/gaming/pegasus.nix) launches every game with `lutris lutris:rungame/<slug>`. Lutris global system.yml has `prelaunch_command: start-game-recording`, `postexit_command: stop-game-recording`, `mangohud: true`, `disable_runtime: true`, env PROTON_ENABLE_WAYLAND=1, game_path /mnt/games/prefixes. Runner wine.yml: version proton-ge (also proton-em, proton-cachyos installed as Lutris wine runners from Nix). 30 wine games each with prefix /mnt/games/prefixes/<slug>; 14 Switch (yuzu runner repointed to eden-pad), 6 dolphin, 2 rpcs3, 1 melonds. Emulator runners use `runner_executable` pointing at `<emu>-pad` wrappers. Per-game env examples: PROTON_SONY_HIDRAW_XINPUT=1, LC_ALL=''. AC Odyssey overrides wine to `system` with esync/fsync off and a per-game prelaunch script. 5 games carry Lutris `script:` blocks that are one-shot installer records (run a repack/GOG Setup.exe into a prefix): cyberpunk-2077, hollow-knight, resident-evil-4-remake, dishonored, the-technomancer (GOG autosetup). Playtime and lastplayed live ONLY in Lutris pga.db (games.playtime hours, games.lastplayed epoch). Installs are handled by a separate `game` script + gogdl ("only puts files on disk; prefixes and launching stay with Lutris"). Steam, Heroic, umu-launcher, protonup-qt are installed but unused by the library.

### Recording
Lutris hook -> `systemctl --user start game-recording.service`. ExecStartPre waits for a game process (pgrep on stems: gamescope wineserver dolphin rpcs3 ryujinx eden mgba melonds pcsx2 cemu azahar shadps4) then for a window filling >=90% of its monitor (gjs script using Mutter DisplayConfig + a custom GNOME extension "GameShot" GetFocusedWindowRect). Then `gpu-screen-recorder -w portal -restore-portal-session no -f 60 -fm vfr -c mkv -k av1_10bit -ac opus -a default_output -a default_input -s 3840x2160 -ffmpeg-video-opts rc_mode=QVBR;...`. The portal picker is shown EVERY launch on purpose: picking the game WINDOW gives one recording that follows a mid-session monitor->TV switch. If not granted in 60 s, fallback: resolve the connector of the focused window (Mutter DisplayConfig -> DRM name) and KMS-capture `-w DP-1` (gsr-kms-server). A watchdog stops the unit when no game process remains (60 s grace, 4 misses x 15 s). ExecStopPost: process-game-recording.mjs (zx): trash < 240 s, move to /mnt/recordings/games/<gameKey>/NNN-YYYYMMDD-HHMMSS-<dur>.mkv, thumbnail, clickable notification, write handoff JSON, kick the journal queue and pegasus-sync.

### Journal (AI)
Queue unit drains handoffs serially. game-session-summary.mjs (zx): curated screenshots from ~/Documents/notes/games/journal/<gameKey>/attachments/*.png in the session window + frames sampled from the mkv (ffmpeg + ImageMagick hashing, up to 40 images) -> `codex exec` (OpenAI Codex CLI, model gpt-5.6-sol, ChatGPT auth, strict JSON schema: title, body, next, images, memory{synopsis, entities, language, profile}) -> markdown note per game `<Display Name>.md`, newest entry first, frontmatter (game, sessions, first_played, last_played, cover), `<!-- session: id -->` markers, per-game .game-memory.json. Written in the game's on-screen language. Usage-limit pause, retries, locks. Manual CLI `game-journal` (--shots, --remove, --renumber).

### Controller shortcuts
Two system services (controller_sdl.py for DualSense/DS4/Nintendo/8BitDo/generic via SDL2; controller_evdev.py for Xbox Elite 2 via evdev/hidraw paddles). Actions: screenshot (gdbus -> GNOME extension com.ilyasturki.GameShot.CaptureWindow, saved to journal attachments/<ts>.png, game from ~/.local/state/current-game.txt), mangohud toggle (uinput Super_L+F12), volume up/down (uinput Shift+VolumeUp/Down). Started by udev rules on pad connect. GNOME-only for screenshots.

### Unified pad ("emu-pad")
InputPlumber (ShadowBlip) is enabled but idle; `emu-pad` wrapper restarts inputplumber, `inputplumber devices manage-all --enable`, waits for a CompositeDevice, runs the emulator, releases on exit. Every pad is pinned to target `ds5-edge` (virtual DualSense Edge) via /etc/inputplumber/devices.d configs, so emulator bindings keyed on SDL GUID survive pad swaps. Patches carried: inputplumber ds5 accel passthrough; pegasus-frontend gamepad unknown-iid crash guard (so a Pegasus fork cost is partially paid already).

### Sessions
Pegasus currently runs INSIDE GNOME (Wayland). A GDM session "Pegasus" exists: `gamescope --backend drm --prefer-vk-device 1002:744c --prefer-output DP-1 --rt --adaptive-sync -e -f --xwayland-count 2 -- pegasus-fe` (QT_QPA_PLATFORM=xcb). OpenGamepadUI is installed with `programs.opengamepadui.gamescopeSession.enable = true` (since May 2026) but not used. Launch splash: Pegasus `scripts/game-start` hook runs a theme-shipped `qml` splash process covering the Pegasus teardown (needs xdotool/xprop under gamescope).

### pegasus-sync.py (2.5k lines Python)
Reads Lutris pga.db (games, categories), Lutris coverart/banners, SteamGridDB, RAWG, Steam store screenshots, the recordings dir (count = play count; newest mkv -> 20 s H.264 trailer clip), journal attachments; writes per-platform `metadata.pegasus.txt` (+ x-metacritic, x-hltb-* extra fields), media/, game_dirs.txt, and REWRITES Pegasus stats.db plays rows from Lutris playtime split across the recording count. Has a --gallery local web UI for artwork.

### Reprise's actual dependency on Pegasus (measured)
api surface used: api.keys.is{Accept,Cancel,Filters,Details,PageUp,PageDown,PrevPage,NextPage,Menu}, api.allGames(.count,.get), api.collections(.count,.get), api.memory.{get,set,has}. Game fields: title, favorite, playTime, playCount, lastPlayed, releaseYear, collections, developerList, publisherList, genreList, players, description, summary, extra, launch(), assets.{boxFront,tile,background,logo,screenshotList}. QML imports: QtQuick 2.15, QtQuick.Window, QtGraphicalEffects 1.15 (blur/opacity masks), QtMultimedia 5.15 (UI sounds), SortFilterProxyModel 0.2 (bundled by Pegasus). Pegasus is GPLv3 (C++/Qt5.15/SDL2); Reprise is MIT.

### External facts already checked
- Pegasus Frontend: last tag Oct 2024; commits on master June-July 2026 (GameDataCache, scan-on-launch). No plugin API. Themes can read local files via XMLHttpRequest only with QML_XHR_ALLOW_FILE_READ=1 (settable on the wrapper) or Qt.labs.folderlistmodel; a theme cannot spawn processes except through game launch commands. Hooks: game-start, game-end, quit, reboot, shutdown, config-changed, controls-changed, settings-changed.
- OpenGamepadUI: Godot 4.7.1, GPLv3, v0.46.1 (2026-09-03) fixed rendering on GNOME desktop; core/systems include bluetooth, network, overlay, performance, power, input (InputPlumber), library, store, launcher, gamescope, mangoapp, notification, plugin. Plugins = zip resource packs with plugin.json, arbitrary GDScript, "can modify nearly all aspects". Official plugins: OpenGamepadUI-lutris (uses `lutris --list-games -j`, last commit Jan 2026), OpenGamepadUI-steam. README: "very early stages of development".
- gpu-screen-recorder: -w accepts monitor name | screen | window | focused | portal | region; KMS capture on Wayland needs gsr-kms-server (setuid helper, already installed via programs.gpu-screen-recorder); -r replay mode with gsr-cli save-replay.
