# CONTEXT v2 — round 2 (2026-09-10). Read CONTEXT.md first, then this. This file wins on conflicts.

## What the project is now
A Linux-only **core** ("Coulisses": daemon + launcher + D-Bus API + data) with **several possible frontends**. Reprise (the existing QML theme, ~5.4k LOC, MIT) is the first frontend. A GTK frontend (Cartridges-like) or a Windows one must be possible later without touching the core. Open source, data human-readable, "conçu pour publier".

## User decisions from today's interview (binding)
- **Languages the user will maintain: Rust, Python, Go. NOT C++.** So the QML host cannot be hand-written C++; it is PySide6 (Python) or cxx-qt/qmetaobject-rs (Rust). Research decides. User has shipped Rust (whisrs, crates.io, with a GNOME Shell overlay extension) and Go (phasionary); Python scripts are "quick hacks". User doubts Python is "native"/fast enough; if research still says Python, it must argue it explicitly.
- **MVP scope**: GOG library (via gogdl as `game` does today), launch via umu-run replacing Lutris, sessions + playtime owned by the app, dialog-free recording, AI journal, per-game settings (hide cursor, capture cursor in recording, env, proton version, pre/post hooks, working dir, esync/fsync), automatic artwork (SGDB/RAWG/Steam like pegasus-sync), GOG update tracking (`game list/update`). Emulation is out of the MVP.
- **Modules**: everything else is an opt-in module that third parties must be able to write later: InputPlumber unified pads (its purpose is emulation: one pad identity across emulators), Bluetooth pairing UI, controller remap editor, gamescope session mode, in-game overlay (PlayStation-style menu on Guide button: pause game, screenshot, recording, settings), emulation, trailer clip cut from own recordings, tracker replacement. Module contract design is a research item.
- **Data**: plain files are the source of truth (one TOML per game, Markdown journal, sessions as JSONL per game); SQLite is a rebuildable index only.
- **Tracker** (~/Documents/notes/games, plain Markdown tables + .data/games.json + covers): the app FEEDS it (Hours column, journal link), does not replace it.
- **TV/desktop switch mid-session is NOT a requirement anymore** (user-specific). Requirement: recording attaches to the display the game is on, no dialog, no mouse. Mouse cursor captured only if the per-game setting says so (`gsr -cursor yes|no`).
- Reprise `main` becomes the Qt 6 frontend; Pegasus-theme compatibility frozen at a tag (assumption, not vetoed).
