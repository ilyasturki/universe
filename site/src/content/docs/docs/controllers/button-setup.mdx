Universe already knows the buttons of most pads ([Supported controllers](/docs/controllers/supported/)). Set them up when a button lands in the wrong place or reads **Unbound**, or when Universe doesn't know the pad.

## Settings › Controller

Settings › **Controller** shows the pad Universe reads, on a card titled with its family, such as "DualSense Edge" ("Controller" for a pad with no family). [Controller](/docs/settings/controller/) describes every row.

<Shot name="settings-controller" />

- **Controller**, with two pads or more connected, picks the pad the card shows.
- **Test the buttons** starts the [button test](/docs/controllers/button-setup/#test-the-buttons), and **Set up the buttons** the [guided setup](/docs/controllers/button-setup/#set-up-the-buttons).
- **Nintendo games** sets where **A** sits in Nintendo games for every pad of this model ([Emulator controls](/docs/controllers/emulator-controls/#where-a-sits-in-nintendo-games)). Only the Emulator controls module reads it, so with that module off it changes nothing.
- Each button has a row, the extra buttons first, that names its [macros](/docs/controllers/macros/). **Unbound** there means the pad sends no code for that button on this connection.
- **Advanced** opens the Timing and HOME settings ([Macros and paddles](/docs/controllers/macros/#timing)).

**A** on a button's row opens a menu with **Learn the button** (**Learn the button again** once it has a code), **On press…**, **On hold…**, and **Clear press** or **Clear hold**. The HOME row offers learning alone.

While a game started from the command line holds the pads, the card reads **Macros are running in the game session**. You can still bind macros then, but the test, the setup and learning wait for that game to end.

The Switch 2 look has this page as **Controllers**, in the HOME menu and in System Settings. The PS5 look has it under Settings › **Controllers**.

## Set up the buttons

1. Press **A** on **Set up the buttons**. The pad drawing fills the page, and the button it wants pulses, with a prompt such as "Press A" or "Pull LT" in the family's own names ("Press Cross" on a DualSense).
2. Press that button. Universe takes its code and asks for the next one. A step you don't answer is skipped after 8 seconds.
3. The 17 standard buttons come first, then the model's extra buttons. Last, hold each stick right, then down, past 40% for a moment.

Meanwhile the pad moves nothing on screen. Steer the setup from the keyboard, or click or tap the actions under the prompt:

- **Previous button (←)** asks the last step again.
- **Keep and finish (Enter)** stops and keeps what is set up so far.
- **Cancel, undo all (Esc)** stops and puts every button and stick back the way it was.

With a pad alone, let the remaining steps time out and the setup ends by itself.

A button an earlier step already took moves to the current step, and the earlier step counts as skipped. The setup ends with a tally of what it set up and skipped.

Leaving the page, another app taking the focus, or the pad going away stops the setup and keeps what it set up.

## Learn one button

To fix one button, or to give a code to one that reads **Unbound**:

1. Press **A** on its row, then **Learn the button** or **Learn the button again**.
2. When the row reads "Press the button on the pad…", press the button you want there.
3. Universe names the code it took, as in "Share is now KEY_RECORD".

Any button on that pad counts as the answer, **B** included, so stop without learning with <kbd>Esc</kbd>. Learning also stops after 30 seconds with no press.

A code that belonged to another button moves over. A pad with no HOME button can get one by learning the HOME row from a spare button.

Outside learning, a press that no button owns shows its code on the card for a few seconds, ready to learn from a row.

## Test the buttons

**Test the buttons** shows what the pad sends. A press lights its button, and each stick and trigger shows its lean or its pull in percent. A dashed button sends no code on this connection; learn it from its row.

The **HISTORY** column lists each press with the time since the one before, and marks a gap under 30 ms, which means the pad sent one press twice.

The pad drives nothing in the menus during the test. To leave it:

- hold the right-hand face button for a second (**B** on an Xbox pad, ○ on a PlayStation pad, A on a Nintendo pad);
- press **Start** and **Select** together;
- press <kbd>Esc</kbd>.

It also ends when you leave the section or the pad goes away.

## The setup offer

The first time Universe sees a pad of a model you have never set up, it offers to set up its buttons. **Set up** starts the guided setup. **Not now** stops the question for that model. A model with learned buttons in `config.toml` is never asked about.

## Where learned buttons are kept

What you learn goes to `config.toml`, per model, and every pad of that family follows it:

```toml
[controller.buttons.xbox-elite]
paddle_p1 = ["BTN_TRIGGER_HAPPY8"]
paddle_p2 = []

[controller.axes.8bitdo-pro-3]
rx = "ABS_Z"
ry = "ABS_RZ-"
```

Under `[controller.buttons.<family>]`, a button's learned list replaces the codes Universe ships for it, and an empty list leaves it unbound. Under `[controller.axes.<family>]`, each stick axis and trigger (`lx`, `ly`, `rx`, `ry`, `lt`, `rt`) names its learned axis, with a trailing `-` when it runs backwards. The button and family ids are in [Supported controllers](/docs/controllers/supported/#controller-families).

## From the command line

[`universe controller ls`](/docs/reference/cli/controller/) lists each connected pad with its id (its input node, such as `event30`), name, family and connection, then its buttons with their codes and macros. `universe --json controller ls` adds the button ids and every code each one answers to.

```sh
universe controller learn xbox-elite paddle_p1
universe controller forget xbox-elite paddle_p1
```

`learn` waits up to 30 seconds for a press on a connected pad of that family and gives its code to the button. It reads buttons and the D-pad only, so learn a trigger or a stick in the guided setup. `forget` puts back the codes Universe ships for that button. To forget a learned stick or trigger axis, run `universe config set controller.axes.<family>.<axis>` with no value.

## Universe Desktop

[Universe Desktop](/docs/using/universe-desktop/)'s Preferences › **Controller** has **Test the Buttons**, **Set Up the Buttons**, **Nintendo Games**, and one row per button. A button's page has **Learn the Button**, **Restore the Default Codes** and its **Press** and **Hold** macros. With no pad connected, **Controller Type** picks the model, so you can bind a model's macros without its pad. While Big Screen is open it holds the pads, and the test, learning and setup wait until it closes.
