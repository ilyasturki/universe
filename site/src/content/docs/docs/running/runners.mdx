A runner is what starts a game. Windows games run on Proton, through umu-run, or on Wine; a Linux game runs as it is, on the runner called Linux; console games run in an emulator such as Dolphin, Eden, Ryujinx, RPCS3 or PCSX2. The [runner list](/docs/reference/runners/) gives every runner with its platforms, file types and options.

## A game's runner

A game with no runner set runs on Proton, and so does a store game, unless the store installed a Linux build, which runs as it is. An emulated game Universe found in an emulator's game folders gets that emulator. When you [add a file by hand](/docs/library/add-a-game/), the runner picker puts first the runners that open that kind of file, the ones on this machine before the missing ones, and Proton before Wine.

To change it, open the game's **Game settings** and pick another **Runner** in the **Launch** card. That's also where a native game that landed on Proton goes back to Linux. From a terminal, [`universe set`](/docs/reference/cli/set/) takes the runner's id or one of its aliases (`yuzu` sets Eden):

```sh
universe set <game> runner=linux
```

When a game's runner is missing at launch and Universe can download it, it offers to install it first, with **Install and play**.

## Emulators & Proton

Settings › **Emulators & Proton** lists the runners found on this machine, the ones with the most games first. Each row gives the number of games on it and the build in use with its origin: Universe, Nix, system, Steam, Lutris, Heroic, umu, your proton folder or config.toml. A tag appears when something wants doing:

- **Needed** when a game uses it and no build is installed.
- **Install …** when Universe can install a newer build beside the one it found.
- **Update …** when there is a newer build than the one Universe installed.
- **Updated** when Universe updated it in the last week.

Under them come **Not installed** (runners Universe downloads and keeps up to date), **No download** (runners you install from your distribution, since upstream ships no build Universe can fetch) and **Tools**. The tools are ludusavi, the stores' gogdl, legendary, comet and butler, and gamescope, MangoHud and gpu-screen-recorder from your distribution.

**A** opens a runner's page or a tool's menu. **X** (**Refresh**) fetches the catalogue of builds again; when it can't be reached, the page says so and shows the last one it fetched. **Y** (**Hide progress**) hides the bar of an install in progress. In the Switch 2 and PS5 looks, **Y** refreshes and **X** hides the bar.

### A runner's page

The page's head names the runner's platforms and the path of its program, or warns **not found**. On Proton's page, **Proton not found** means no build matches the Proton build setting. The cards follow:

- **Runner** holds **Program**, the program Universe found and where from (**Found on PATH**, or **Installed by Universe** with its version). On an emulator's page you can set your own path there, and **Arguments** go to the emulator for every game on it. **Gamescope** decides whether this runner's games get a gamescope of their own, unless a game sets its own (see [Gamescope, HDR and frame rate](/docs/running/gamescope/)).
- **Builds** lists what Universe can install for this runner. On Proton's page it opens with **Proton build**, the build every Proton game runs with unless it names its own, then GE-Proton, Proton-CachyOS, Proton-EM and UMU-Proton.
- Next come the defaults for this kind of game. Proton's page has **Wayland**, **HDR** and **PlayStation controller**, and under Show advanced the sync modes, the upscaler upgrades and **Debug log**. [Launch settings](/docs/running/launch-settings/) explains how they sit under each game's own.
- **Options** holds an emulator's own options, such as fullscreen, quitting with the game or a user folder.
- **Games** lists every game on this runner with its play time. **A** on one offers **Game settings**, **Uninstall…** (for a game with an install folder) and **Remove from library…**. **Add a game…**, at the end, picks a file and adds it on this runner.

On Proton's page, **Program** shows the umu-run Universe found, with the umu-launcher row under it. Launches use the umu-run named in **umu-run program**, in Settings › **Game defaults** under Show advanced. When it isn't on the machine, Universe fetches umu-launcher before the first Proton launch.

**X** puts a row back to what Universe found or to the default, and **Y** shows the advanced rows.

## Builds Universe installs

Universe installs Proton builds, emulators and tools from its catalogue into `~/.local/share/universe/components/`, one folder per version. **A** on a build's row opens its menu:

- **Install …** installs the newest build. When another build is in use, it reads **Install … and use it** and switches to the new one.
- **Update to …** installs a newer build.
- **Use …** switches to another build, one of Universe's or one it found.
- **Follow the newest …** always takes the newest build: Universe's newest for an emulator, and for Proton the newest of that family wherever it's installed.
- **Install another version…** offers the older versions.
- **Roll back …** removes Universe's newest build and skips that version, and the version after it updates as usual.
- **Remove …** deletes one build, and **Uninstall** all of Universe's builds of it.

An update keeps the newest two builds, plus any build a setting or a game names and the one a running game uses. Updates wait while a game runs. A build that something still names can't be removed until you pick another one for it.

With automatic updates on (`components.auto_update`, the default), Universe looks for updates 90 seconds after it starts and then once a day, never during a game or another install. A notice says what it updated.

Your distribution provides gamescope, MangoHud and gpu-screen-recorder. Where PackageKit can install one, its menu's **Install from the distribution** installs the package and asks for your password, except in [the Universe session](/docs/getting-started/universe-session/). On NixOS, the emulator and Wine builds Universe downloads run inside `universe-fhs`, and System check makes sure it's there.

## Builds already on the machine

Universe lists the builds it finds next to its own, and **Use …** switches between them. For an emulator or Wine, the runner's build setting decides which one runs:

- by default, the program on your PATH, else Universe's newest build;
- after **Follow the newest …** (`build = "latest"`), Universe's newest first;
- after **Use …** on one of Universe's builds, that version.

A **Program** path you set wins over all three. Universe looks on your PATH for the program names the [runner list](/docs/reference/runners/) gives, so it doesn't find an emulator installed as a Flatpak. For one game, the **Launch** card of its Game settings has a program row named after the emulator (**Dolphin program**), and `universe set <game> runner_build=<version>` picks one of Universe's builds.

## Proton builds

**Proton build** names the build a game runs with, `proton-ge` by default. Universe looks for that name in this order and takes the first match:

1. `~/.local/share/universe/proton/`, your proton folder;
2. an entry in `[proton]` of config.toml (Settings › Game defaults › **Proton builds**, under Show advanced);
3. the name itself, when it's a path;
4. a folder with that name among Universe's builds, Lutris's `runners/wine`, Steam's `compatibilitytools.d` (Flatpak Steam's too), umu's `compatibilitytools` and Heroic's `tools/proton`;
5. the newest build of that family in any of these folders, so `proton-ge` finds GE-Proton10-12 before GE-Proton9-27.

When nothing matches, the GE family's name (`proton-ge` or `GE-Proton`) makes umu-run download the latest GE-Proton at the first launch. Any other name runs on umu-run's own UMU-Proton, and System check flags it.

The **Proton build** picker lists your `[proton]` names and every build found. Set one game's in the **Proton** card of its Game settings, or from a terminal:

```sh
universe set <game> proton=GE-Proton10-12
universe component install ge-proton
universe component use ge-proton latest
```

The last line makes `proton-ge` the default again, which follows the newest GE-Proton.

## From the command line

[`universe runner`](/docs/reference/cli/runner/) lists the runners and sets their keys, and [`universe component`](/docs/reference/cli/component/) handles the builds:

```sh
universe runner ls
universe runner options dolphin
universe runner set dolphin batch=false
universe runner set eden build=latest
universe component ls
universe component update
universe component rollback eden
universe component use eden system
universe component remove eden <version>
universe component uninstall eden
```

`runner set` takes `exe`, `args`, `gamescope`, `build` and the runner's options, and an empty value (`exe=`) resets one. `component use` takes `latest`, `system` or a version. `component install` takes a version after the id, and `--yes` accepts a build's notice without asking.
